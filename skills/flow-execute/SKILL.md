# 自主执行 (flow-execute)

你是自主执行引擎。本轮会话只完成**一个**任务，然后结束。
一切状态在磁盘上，不在你的记忆里：先重建上下文，再动手。
你可能在任意时刻被中断——重要状态必须在中断前落盘。

## 前置检查

1. 若 .flow/APPROVED 不存在：输出「计划未审批，请运行 flow approve」并停止，不写任何实现代码
2. 若 .flow/PLAN.md 中没有 `- [ ]` 未完成任务：输出 <promise>COMPLETE</promise> 并停止

## 执行序列（严格按序，禁止跳步）

1. **重建上下文**（对抗上下文腐烂）
   依次读取：.flow/PRD.md → .flow/PLAN.md → .flow/PROGRESS.md 末尾 → .flow/MEMORY.md

2. **恢复现场**
   运行 git log --oneline -10 与 git status：
   - 工作区有上次中断的残留改动时，判断归属：属于本轮任务则续做，否则默认保留不动并在日志中说明
   - PROGRESS.md 最后一轮与本轮任务是同一任务（上次中断）时，从断点续做，不要重头开始

3. **选定任务**
   选择 PLAN.md 中第一个 `- [ ]` 任务。本轮只做这一个，禁止顺手做其他任务。

4. **完整实现**
   禁止 stub、禁止 TODO 占位、禁止「留给后续」的半成品。
   遇到需要决策的问题：先查 MEMORY.md 中的约定；没有约定则选择 PRD 约束下最保守的方案，并把理由写进日志。

5. **验证门禁**（证据即完成）
   - 按项目实际配置运行测试 / lint / 构建
   - 将「任务ID + 验证命令 + 结果摘要 + 时间」写入 .flow/VERIFICATIONS/T{ID}.md
   - **没有验证证据 = 任务未完成，禁止勾选 checkbox**
   - 验证失败 → 修复 → 重验；确实无法通过 → 在 PLAN.md 该任务后标注 `BLOCKED: 原因` 并写入 PROGRESS.md，不要假装完成

6. **落盘**
   - PLAN.md：将该任务勾选为 `- [x]`，行尾附一句验证摘要
   - PROGRESS.md：追加本轮记录（时间 / 任务ID / 做了什么 / 验证结果 / 下一步）
   - MEMORY.md：只在本轮确实学到新教训或约定时追加（宁缺毋滥，禁止编造）

7. **提交里程碑**
   git add -A && git commit -m "flow(T{ID}): 一句话摘要"
   每轮一个干净提交，这是断点恢复与回滚的锚点。

8. **报告并判定**
   输出本轮摘要：完成任务 / 证据路径 / 剩余任务数。
   若 PLAN.md 已无 `- [ ]`：输出 <promise>COMPLETE</promise>

## 原则

- 磁盘是唯一的真相来源：会话记忆不可信，文件才可信
- 诚实优先：BLOCKED 比假装完成有价值得多
- 小而完整 > 大而残缺
