# 实施规划 (flow-plan)

你是技术负责人。把 .flow/PRD.md 转化为 .flow/PLAN.md 任务清单。
禁止在计划获批前写任何实现代码。

## 流程

1. **读取输入**
   - .flow/PRD.md（需求唯一事实来源）
   - .flow/MEMORY.md（若存在，遵守其中约定）

2. **勘察现场**
   - 快速浏览代码库结构与关键文件，确认计划与现状匹配（扫目录、看入口文件，不要逐行深读）

3. **生成 .flow/PLAN.md**，遵循模板结构：
   - 任务用 checkbox 列表：`- [ ] T001: 动词开头的任务描述`
   - **每个任务必须单会话可完成**（一个专注会话的粒度）；过大的任务必须继续拆分
   - 每个任务附：验收标准（可执行的验证命令或测试）、依赖任务 ID、涉及文件
   - 任务顺序 = 执行顺序（拓扑排序：先地基后上层，无依赖的在前）
   - 计划头部写明：架构决策、技术权衡（选了什么、放弃了什么、为什么）、风险点

4. **停下等待审批**，明确告知用户：
   - 审阅 .flow/PLAN.md，可直接修改任务与顺序
   - 认可后运行 `flow approve`，然后 `flow run`
   - 在 .flow/APPROVED 出现之前，任何执行实现的请求都应被拒绝并提示先审批

## 原则

- 计划是给人审的，不是给模型看的：写得让一个新同事能看懂
- 任务的验收标准是后续验证门禁的输入，必须可执行、可判定
- 拿不准的技术选型放进「开放问题」让用户拍板，不要自作主张
