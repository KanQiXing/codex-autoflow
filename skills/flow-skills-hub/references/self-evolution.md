# 技能自进化指南（蒸馏自 Tencent/SkillHone 149★）

## 核心理念

技能不是写完就不动的静态文档。每次使用产生的决策记录是技能优化的燃料。

## 决策记录机制

每个技能目录下维护一个 `DECISIONS.md`（追加式，不删改）：

```markdown
## 2026-09-12 T15:30 — flow-plan 触发
- 用户意图: "给系统加认证"
- 选择了: 拆分为 7 个单会话任务
- 跳过了: 用户不需要 OAuth，只需 session
- 用户修改: 把任务 3 和 4 合并了
- 教训: 认证模块的迁移和模型应该在同一会话完成
```

## 进化循环

```
使用 → 记录决策 → 累积 10+ 条 → reviewer 审计 → 提议优化 → 人工确认 → 更新 SKILL.md
```

### reviewer 审计清单

1. **description**: 触发词是否覆盖了实际使用场景？是否过宽导致误触发？
2. **正文指令**: 有没有反复被用户跳过的步骤？有没有用户每次都补充的步骤？
3. **references**: 有没有从未被读取的文档？（可删除或合并）

### 与 flow MEMORY.md 的分工

| 机制 | 粒度 | 位置 | 用途 |
|------|------|------|------|
| `DECISIONS.md` | 单技能级 | 各技能目录 | 该技能的使用模式优化 |
| `MEMORY.md` | 项目级 | `.flow/` | 跨技能的教训与约定 |

## 实现要点

- `DECISIONS.md` 由技能正文指示 Codex 在每次执行后追加（不是自动的，靠 prompt 约束）
- 积累后，用户可运行 `flow review` 让 reviewer 子代理审计全部技能的 `DECISIONS.md`，产出优化建议
- 这是 SkillHone "whole-skill optimisation" 的轻量 bash 实现：去掉其 Git issue/PR/wiki 自动化，保留决策→审计→优化的核心循环
